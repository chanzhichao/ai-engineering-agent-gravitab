

| Project Name | Agent Gravitab |
| :---- | :---- |
| **Domain** | Productivity / Multi-Agent Systems (Browser Intelligence & Context Management) |
| **Problem Statement** | Knowledge workers, researchers, and students constantly struggle with "tab overload," accumulating dozens or hundreds of open browser tabs that lead to high cognitive load, context-switching fatigue, and severe productivity loss. AI engineering makes it possible to build a multi-agent coordination pipeline where specialized domain agents analyze tab metadata, semantic intent, and urgency to autonomously organize, categorize, and optimize active web workspaces under strict user preference constraints. |
| **Evidence of the Problem** | “Knowledge workers experience frequent fragmentation of attention and severe cognitive overhead due to digital clutter and unmanaged information streams, leading to measurable losses in task efficiency and focus.”**Citation:** Mark, G., Gudith, D., & Klocke, U. (2008). The Cost of Interrupted Work: More Speed and Stress. *Proceedings of the SIGCHI Conference on Human Factors in Computing Systems*, 107–110.**URL:** [https\://doi.org/10.1145/1357054.1357072](https://www.google.com/search?q=https://doi.org/10.1145/1357054.1357072) Led by researchers at CMU’s Human-Computer Interaction Institute, it discovered that **25% of users experienced a complete system crash** due to hoarding tabs. The authors detailed the "blackhole effect"—the intense psychological fear that as soon as a tab goes out of sight, the thought or task is lost forever.**Citation**: Aupperlee, A. (2021, May 10). *Overcoming tab overload*. Carnegie Mellon University.**URL**: [https\://www\.cmu.edu/news/stories/archives/2021/may/overcoming-tab-overload.html](https://www.cmu.edu/news/stories/archives/2021/may/overcoming-tab-overload.html) |
| **Engineering Gap / Limitation** | Existing browser organization tools either rely on rigid, manual folder hierarchies that fail to adapt to dynamic workflows, or unconstrained LLMs that lack structured multi-dimensional classification (balancing project context, semantic similarity, recency, and active priority concurrently) and fail to respect local data privacy boundaries. |
| **Initial Project Objectives** | **O1:** To design a multi-agent tab organization architecture featuring specialized domain agents (Semantic Topic, Urgency/Recency, Project Context, and Privacy/Security) and a central Aggregator/Planner. **O2:** To develop the system using local vector embeddings and ranking algorithms combined with agentic workflows to generate clean, categorized workspace sessions and automated tab management actions. **O3:** To evaluate the solution in terms of categorization accuracy, retrieval precision for natural language queries, system latency, and reduction in user context-switching overhead. |
| **Target Users** | Students, software engineers, researchers, and heavy web users who juggle multiple projects simultaneously and suffer from productivity loss due to manual tab management. |
| **Data Sources** | **Source 1:** Browser Extension APIs (chrome.tabs, chrome.history, chrome.bookmarks and session metadata) **Source 2:** Local Vector Embeddings / Semantic Knowledge Base (Generated locally via lightweight models like Transformers.js or local embedding endpoints to cluster webpage titles and content snippets). |
| **Similar to EduAdvisor** | Both systems ingest structured reference domains (academic policies vs. browser telemetry and user project taxonomies), use structured parsing layers, and ground their automated outputs in authoritative data sources rather than unconstrained text generation. |
| **Different from EduAdvisor** | *EduAdvisor* is a **Retrieval-Augmented Generation (RAG) system** that searches an information base and generates advisory text, which is static. *Agent Gravitab* is a **Multi-Agent Optimization and Action Engine** where specialized agents negotiate and feed data into a decision-making/ranking algorithm to actively group, sort, and manage browser states, which is dynamic and time dependent. |
| **Responsible AI Risks** | **Risk 1 —** Privacy & Data Leakage: Processing sensitive browsing history or private tab contents exposes user data to external LLM endpoints. *(Mitigated by local-first embedding generation, client-side processing, and strict opt-in privacy policies).* **Risk 2 —** Misclassification / Data Loss: The agent incorrectly categorizes or automatically hibernates critical temporary tabs, disrupting active user workflows. *(Mitigated by explicit user confirmation steps, undo states, and configurable auto-hibernation rules).* **Risk 3 —** Resource Overhead: Running multi-agent classification loops and local embedding pipelines directly in the browser consumes excessive CPU and memory. *(Mitigated by efficient asynchronous batching, lightweight embedding models, and on-demand execution triggers).* |
